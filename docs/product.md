# skillcab 产品方案

状态：V0.3 已实现盘点、安装/卸载、来源登记和更新检查；覆盖更新仍为后续规划。2026 年 11 月 21 日。

## 定位

面向使用 Codex、Claude Code、Cursor 等 AI 工具的开发者，以一个 npm 包提供 CLI 和本地 Web UI。直接读取已有全局及项目 Skill，兼容 Skills CLI 安装、手工复制、软链接和外部托管，不要求统一迁移到新仓库。

用户应能回答：我装了什么、装在哪里、哪些工具可能读取它、来源是什么、当前版本能否确认、是否有上游更新、更新会影响哪些位置。

没有账号和云端服务要求。默认只监听本机回环地址。npm 包包含编译后的前端和服务端，用户无需运行前端开发服务器。

## V1 里程碑

### A 只读盘点（已交付）

- CLI 启动 Web UI、输出全局或项目扫描的 JSON / 表格。
- 扫描共享目录、Codex、Claude Code、Cursor 目录，以及自定义路径。
- 自动扫描全局；当前目录或通过参数指定的项目可在界面切换；支持登记其他项目。
- 列表支持名称/描述搜索、工具/来源/异常过滤、排序。
- 详情展示 Markdown 正文、元数据、来源证据、安装位置、真实位置、关联工具、锁文件信息、有限深度的资源文件清单。
- 项目视图区分项目内安装和全局可见候选，不声称能确认 Agent 的运行时实际加载/调用。
- 显示手工内容、外部管理、来源未知、坏链接、无效文档、目录不可读和不支持的 lock。
- 刷新重新读取磁盘。读取不完整与空目录有明确区别。
- 扫描不修改 Skill、上游 lock 或安装位置；显式安装和卸载独立走操作层。

### B 可信版本与检查（V0.3 已交付）

- 手工 Skill 关联 Git / 本地来源，选择子目录与跟踪目标，先对比后建立记录。
- 保存可信内容基线；独立展示本地状态和远端状态。
- 分支、标签、固定提交采用不同跟踪策略；固定提交不因分支前进被自动判定为过期。
- 远端检查缓存、并发去重、限流、认证失败和网络错误。
- 完整目录差异包括脚本、资源和删除文件，不只比较 SKILL.md。

### C 可控写入

- 安装、更新、移除关联与删除源内容分开。
- 固定候选内容、预览实际影响位置、备份后执行、结果验证、失败恢复。
- 第一版不自动合并本地修改；保留、导出或由用户明确选择替换。
- 有本地修改、基线未知、格式不支持或状态已变化时，阻止无预览覆盖。

本轮新增：安装来源选择、全局/项目及工具入口选择、安装预览、所选位置卸载、卸载备份与会话内撤销、系统文件管理器打开目录。V0.3 补充手动来源登记、版本证据、单项/批量更新检查、结果缓存、工具 Logo、无需 Token 的后台 Web UI。覆盖更新、自动更新、云同步、市场、AI 推荐、在线编辑器与桌面壳仍在后续范围。

## 信息架构

侧栏为全局 Skills、项目列表、添加项目；主区为列表，选择后进入详情。列表采用面向开发工具的紧凑布局，不以大面积统计卡占据主要内容。

| 区域     | 信息与动作                                              |
| -------- | ------------------------------------------------------- |
| 范围切换 | 全局、已添加项目，展示本机路径                          |
| 列表     | 名称、描述摘要、来源、关联工具、安装/链接状态、版本证据 |
| 筛选     | 搜索、工具、来源类别、异常；显示结果计数                |
| 详情     | 概览、SKILL.md、文件清单、诊断、lock 原始记录（脱敏）   |
| 添加项目 | 服务器验证真实目录，登记到本工具配置，不扫描整个主目录  |
| 刷新     | 重新读取安装和 lock；不会修改它们                       |

空状态应区分没有安装、筛选无结果和读取失败。加载与错误可重试，不能用上一条数据冒充新范围。

## 安装与项目关联

安装是一个指定 scope 的磁盘位置。相同名称可能对应不同来源，相同来源也可能安装了不同版本。安装 ID 不能只由名称生成。

同一真实目录被多个工具目录链接时，在同一 scope 中可合并为一组安装位置展示，但保留每个入口和诊断。不同 scope 不合并，更新时才能算清关联影响。

共享目录里的内容是工具读取规则下的可见候选，不是“所有工具都已启用”。全局与项目同名同时存在时展示并存，只有已确认具体工具优先级才标记覆盖。

## 版本和来源证据

Skill 标准不强制版本号。作者声明的版本、来源 ref、commit、内容指纹是不同信息，应分别展示。

- `metadata.version`：作者声明版本，仅供参考。
- lock 中 commit：记录的安装提交；必须标注是记录值，尚未重放核验。
- branch/tag/ref：来源跟踪目标，不等同当前安装内容版本。
- skillFolderHash/computedHash：标注算法和证据来源，不把不同算法互相比。
- 手工目录且没有来源：本地内容，历史版本未知。

仅在 lock 与实际位置的对应关系有足够证据时附加来源。不能把同名的项目 lock 记录自动套到全局安装。无 lock 的软链接副本也不能只凭同名认定为 CLI 管理。

来源未知、手工安装与无效文档是三个不同维度。手工目录也可能有可确认来源；无效文档仍保留在盘点中。

## 手工内容纳管（B 阶段）

选择本地内容 → 填写来源 → 选择上游子目录及 ref → 对比内容 → 建立关联。

- 内容完全一致时建立可信基线。
- 内容不同时标记“历史基线未知”，不能据此认定是用户修改或自动覆盖。
- 来源候选必须用户选择，不按名称猜仓库。
- 记录写入本工具元数据，不改 SKILL.md，不把未核实来源伪装成 CLI 安装记录。
- 内置、插件缓存、npm 依赖等外部管理内容展示原管理方式，升级交回原工具。

## 验收

1. 通过一条命令启动生产构建，并在浏览器看到真实全局内容。
2. 添加含不同工具目录的项目，能切换、搜索、打开详情和资源清单。
3. CLI JSON 与 Web 列表使用同一扫描模型。
4. 正确展示普通目录、有效/失效软链接、同名不同来源、共享 realpath。
5. 缺失/无效/未知格式 lock 不导致现有安装消失。
6. SKILL.md 不合法、无法读取时依然显示条目和诊断。
7. 扫描前后 Skill 与 lock 文件内容、链接和位置不变。
8. Markdown 不执行 HTML/脚本；API 不向任意网站泄露本地文档。

## V0.2 操作边界

安装支持本地目录、Git 仓库与 GitHub tree 目录。来源内容先复制到临时快照，预览固定来源、提交、范围、目标位置及锁记录。已有位置/记录不覆盖，目标目录或锁文件在预览后变化则停止。全局记录写 schema 3；项目保留 schema 1/2 并使用对应内容哈希，不修改其他 Skill 和未知字段。

卸载按实际安装入口操作，默认选择同一范围的整组入口，也可仅移除个别工具链接。移出内容目录前核对已登记项目的已知引用；目录根本身链接到其他位置时保留源内容，交由原目录管理。卸载自动备份，本次会话可撤销，冲突时保留双方文件而非覆盖。

打开目录仅接受已经扫描出的安装 ID 和入口索引，由本机服务调用系统文件管理器，不接受任意客户端路径。文件管理器故障可复制路径手动打开。

## V0.3 验收补充

- `npx skills` 安装按各 scope 锁记录识别来源，显示声明版本或记录提交；不能用仓库整体 HEAD 变化冒充 Skill 更新。
- 列表展示未检查、有更新、最新、版本未知、检查失败、未关联和不支持等状态；“有更新”可筛选。
- 来源补录核验完全一致才建立内容基线；不一致允许登记来源，历史版本仍未知。
- 不修改 Skill 文件和上游 lock；本地变化使缓存失效，错误不误报最新。
- 默认后台启动、重复启动复用、普通本机地址直接访问；提供 status / stop 和前台模式。关闭终端不中断；系统重启后需重新启动。
- 工具标识使用 Logo，保留悬停名称与无障碍标签，共享目录使用单独图标。
